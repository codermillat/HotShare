# HotShare v1.5 — Sideload (No Root, No Play Store)

One APK, dual role. Host serves standard HTTP:8080 + SOCKS5:1080 so ANY client works
(Android app, macOS manual/script). **Works on both 2.4 GHz and 5 GHz hotspots.**
Now with a VPN-app experience: foreground service + status notification, live speed meter,
connection monitor, a Material 3 UI, and custom branding/icons.

> **Authorized use:** share connections you are authorized to share, with devices you own,
> per your provider's terms. MIT License — see the repo `LICENSE` and `THIRD-PARTY_NOTICES.md`
> (hev-socks5-tunnel, ZXing, AndroidX, Kotlin). An in-app "Open-source licenses" notice is included.

## v1.2 changes (all fixes)
- **Dual-band 2.4/5 GHz:** band selector (Auto / 2.4 / 5). API 34+ forces the band;
  older APIs use the system-picked band (both work). UI shows the actual AP band and
  the ISP (STA) band so you can avoid a 5 GHz + 5 GHz single-radio conflict (use 2.4 GHz AP).
- **Auth + hardening:** the proxy binds to the **AP IP** and only accepts **hotspot-subnet
  clients** (the hotspot WPA2 password is the primary gate). A per-session 12-char token is
  embedded in the QR and always sent by the app's VPN; a present token is validated
  (SOCKS5 RFC1929 / HTTP `Proxy-Authorization`). Optional **Require QR token** switch makes
  auth strict (then macOS/manual clients must add `user:token` to their proxy URL).
- **Relay fixes:** removed the 60 s tunnel cap (long downloads/streams survive);
  fixed SOCKS5 UDP ASSOCIATE (client UDP mapping was never learned → QUIC/games failed);
  fixed IPv6 address parsing; removed dead code.
- **TUN:** MTU 1500 (was 8500); clear message when the native tun2socks lib is missing;
  pre-API33 routing-loop protection documented (process bind + underlying network).
- **Manifest:** `foregroundServiceType="connectedDevice"` (+ permission), dropped unused
  `REQUEST_INSTALL_PACKAGES` / `RECEIVE_BOOT_COMPLETED`.
- **Build:** keystore passwords via `HOTSHARE_STORE_PASS` / `HOTSHARE_KEY_PASS` env,
  RSA-3072, version.json auto-derived from gradle.

## Install (manual distribute — Drive / Telegram / USB / Nearby)
1. Copy `HotShare-v1.apk` to phone.
2. Tap APK → Allow `Install unknown apps` for Files/Chrome once → Install.
3. Same APK on both Host + Client phones. No account, works offline.
4. Verify hash: compare with `SHA256.txt` (v1.2):
   `d80e6ad65e624b7c0b987f60fa2411c28fc33ac67de9b3ce6c4fcd8c6a9bdbdb`
5. Update: download new APK, tap to install (same key `hotshare.jks` — keep `keystore/hotshare.jks` safe or reinstall required).

## Use — Host (the phone with the internet connection)
1. Connect the host to your Wi-Fi / upstream network and confirm it has internet.
2. Open HotShare → pick **Hotspot band** (Auto, or match the upstream band on a single-radio phone)
   → `Share Internet (Host)` → starts proxy on the AP IP (`:8080`/`:1080`) + 12-char token.
3. Enable System Hotspot manually if Auto-LOHS fails (Android 10+ blocks auto-enable in some ROMs):
   Settings → Hotspot → ON → Band 2.4 GHz or 5 GHz. Both work; match the upstream band.
4. Keep app foreground (sticky notification). Host IP varies by OEM/band:
   TECNO test device = `10.128.181.87` (subnet `10.128.181.0/24`), stock = `192.168.43.1`.
   Find it on the Host screen or `ip addr show ap0`.

## Use — Client Android (recommended: system proxy — verified working)
1. Join Host hotspot WiFi (manual, or adb: `adb shell cmd wifi connect-network <ssid-escaped> wpa2 <pass>`).
2. Set proxy (pick one):
   - **adb (no root):** `adb shell settings put global http_proxy <host-ip>:8080` → reset `settings put global http_proxy :0`.
   - **UI:** WiFi settings → modify network → Proxy Manual → `<host-ip>:8080`.
3. Verify: browse example.com — traffic should leave through the host's connection.
4. Turn Client cellular data OFF during test to prove all traffic rides the Host.

> Manual proxy needs **no token** (the host only accepts clients from the hotspot subnet).

## Use — Client Android (VPN path — all apps/UDP, authed via QR)
- Join → paste `hotshare://join?...` (or scan the QR) → Connect. The tunnel uses the
  host's SOCKS5 `:1080` with the QR token automatically.
- Needs the native tun2socks lib (bundled in this APK). If it is missing the app says
  `tun2socks lib missing — use system-proxy mode` instead of blackholing.

## Use — macOS Client role (script, sets the system proxy to the Host)
1. Join the host's hotspot over Wi-Fi.
2. Run: `bash scripts/hotshare-mac.sh <host-ip>` (e.g. `10.128.181.87` or `192.168.43.1`),
   or paste the QR URI. Sets the system Web/Secure/SOCKS proxies to the host.
3. Check: `./hotshare-mac.sh status` — via-proxy egress should show the host's public IP.
   Undo: `./hotshare-mac.sh undo`. Works identically for 2.4 GHz and 5 GHz hotspots.

> macOS manual proxy also needs **no token** (subnet-restricted). If you later enable
> token-only mode, add it to the proxy URL as `user:token@`.

## Limits (honest, no-root)
- No ICMP ping (proxy ≠ ping) — apps work, `ping` won't.
- Hotspot must be enabled manually on ROMs that block auto-LOHS. Shizuku/ADB auto-toggle is future.
- Phones without STA+AP concurrency: use USB-tether + same proxy. The UI warns for 5 GHz+5 GHz.
- minSdk 26 (Android 8+) → ~98% devices. targetSdk 36 (Android 16) — required by
  Google Play for submissions since 2026-08-31. AGP 8.13.1 / Gradle 8.13 / Build Tools 36.

## Two-device install via adb
```
bash scripts/install-both.sh dist/HotShare-v1.apk
```

## Rebuild
```
export JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home
export ANDROID_HOME=$HOME/Library/Android/sdk
export HOTSHARE_STORE_PASS=...   # required — there is no default password
export HOTSHARE_KEY_PASS=...
bash scripts/build-apk.sh        # builds + signs + writes dist/ + version.json
```
